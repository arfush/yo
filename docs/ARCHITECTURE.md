# Архитектура

## Верхний уровень

```text
cmd/yo/     только main: root.Run()
root/       composition root: сборка графа и lifecycle, создание экранов
catalog/    DTO проекта
core/       не-UI код: сайты, провайдеры, хранилище, playback, party, обновления
ui/         весь Gio UI: shell, appearance, resource, kit, navigator, экраны
version/    версия приложения
docs/       документация
```

Новый верхнеуровневый модуль — только с разрешения пользователя.

## Направление зависимостей

```text
catalog      → std
core/stdx    → std
core/*       → catalog, core/stdx, core/*
ui/*         → catalog, core/*, ui/*
root         → catalog, core/*, ui/*
cmd/yo       → root
```

- `catalog` не импортирует `core` и `ui`.
- `core` не импортирует `ui` и `root`.
- Циклы запрещены. Если для связи нужен цикл — это ошибка границ, а не повод для интерфейса.

## Термины

- `site` — Yoanime, Yomanga, Yoranobe, Yobase. В коде и документации — `site`, не `domain`.
- `title` — тайтл; `source` — источник; `voice` — озвучка; `season`/`episode` — сезон и серия.
- `history` — прогресс; `reading` — манга или ранобэ; `party` — совместный просмотр.

## Модули

### `root`

Единственное место, где известен полный граф. Создаёт конкретные типы и экраны, связывает их и владеет lifecycle. При сборке передаёт в `ui/navigator` колбэки-фабрики для создания экранов. Типы фабрик живут в `ui/navigator/factory.go`, конкретные методы создания — в `root/screen.go`. Навигацией не управляет: переходы решает `navigator.Navigate()`. Не содержит бизнес-логики, запросов, парсинга и правил предметной области. Ориентир — до 600 строк; если больше, логика уехала не туда.

### `catalog`

Только данные и валидация значений. Никаких ошибок, HTTP, SQL, UI. Один общий набор DTO; не дублируй `catalog.Title` другим `Title` в `core`. Если хранилищу нужны свои строки — держи их приватными в `core/store` и преобразуй на границе.

### `core`

Не-UI код. Подпакеты — это фичи, а не слои:

- `stdx` — расширение стандартной библиотеки: только generic, только std, без предметной области и I/O. Если нужен `catalog` — код не отсюда.
- `log` — журнал.
- `dependency` — установка внешних компонентов (Chromium, mpv).
- `platform` — пути, окно, трей, single instance, установка.
- `store` — SQLite, секреты, история.
- `origin/libsocial` — провайдер семейства сайтов Libsocial: аниме, манга и ранобэ.
- `origin/www` — провайдер кино и сериалов.
- `browser` — Playwright и headless-сценарии.
- `playback` — mpv, очередь, прогресс.
- `party` — совместный просмотр; только когда начнётся этап.
- `update` — обновления; только когда начнётся этап.

`core/party` может импортировать `core/playback`; обратное запрещено. Если нужен обратный вызов — его передаёт `root` или `ui`, а не импорт.

### `ui`

Только показ. Никаких запросов, парсинга, SQL и бизнес-правил.

- `ui/shell` — рамка окна, заголовок, notice, переключение сайта.
- `ui/appearance` — палитра (включая цвета маскота), типографика, язык, форматирование.
- `ui/resource` — встроенные ассеты: иконки, шрифты, изображения, строки; загрузка и кэш.
- `ui/kit` — переиспользуемые виджеты; `ui/kit/mascot` — рисование маскота.
- `ui/navigator` — навигация: `Navigate()`, интенты, `Handler`, стек экранов; вызывает `ui/shell` для заголовка и notice.
- `ui/screen` — экраны. Пакет плоский, без подпакетов: `<feature>.go` — состояние, обработчики и `Layout`; `<feature>_draw.go` — приватные draw-методы. `Layout` ничего не рисует сам, а вызывает их. Общие виджеты — в `ui/kit`.

`ui/appearance` может импортировать `ui/resource`; обратное запрещено. `ui/navigator` импортирует `ui/shell`. Логика переходов живёт в `Navigate()`. `root` при сборке передаёт в `navigator` колбэки-фабрики экранов; пакеты экранов `navigator` не импортирует. `ui/shell` не импортирует `navigator`, экраны и `root`: его события передаются колбэками. Экраны не импортируют `root` и `shell`; переходы — через `ui/navigator`.

## Контракт пакета

У каждого пакета — комментарий-контракт до 20 строк в `doc.go`: назначение, запреты, инварианты. `cmd/*` — исключение: `doc.go` там не нужен. Импорты в контракте не перечисляй: укажи запрещённые подсистемы (`UI` — `ui/*` и `gioui.org/*`, `core` — `core/*`, `root` — `root`); исключение из запрета — только после согласования с пользователем. Если нужно больше, остановись и объясни, почему; пиши по делу, без воды. Переноси строки по смыслу: ориентир — до 100 символов. Не склеивай контракт в одну длинную строку; `gofmt` комментарии не переносит.

```go
// Package playback owns one mpv session: queue, progress and lifecycle.
//
// Must not import: UI (ui/*, gioui.org/*), root.
// Invariants: one session at a time; callbacks run on the UI goroutine.
```

Экспортируемый API — и есть контракт. Не создавай интерфейс на каждый модуль. Интерфейс объявляет потребитель, если ему нужен узкий шов: вторая реализация, тест или внешняя граница. Провайдер отдаёт конкретный тип.

## Асинхронность

Один идиом на проект:

- UI-состояние живёт на UI-горутине;
- фоновая работа возвращает результат через очередь кадра (`root.Post`) или канал;
- `Layout` не блокируется и не запускает горутины;
- отмена — через `context.Context`;
- не изобретай `done func(error)` в каждом пакете.

## Логирование

Один логгер на модуль, передаётся в конструкторе или через `*Options` и хранится в поле. Никаких пакетных логгеров, `slog.Default()` и `init()` с побочными эффектами. Логируй старт/конец внешних операций и ошибки; не логируй каждый кадр. Секреты и пользовательский текст — запрещены.
