# Тесты

## Принцип

Тест защищает поведение и контракт, а не реализацию. Тест, который ломается от переименования приватной функции, — liability, а не страховка.

## Что тестировать

- Чистую логику: парсинг, валидацию, состояния, очередь, прогресс, сравнение версий.
- Границы: провайдеры на записанных фикстурах, миграции БД, раскладку файлов, обновления.
- Ошибки: «не найдено», таймаут, отмена, битые данные, недоступный внешний компонент.
- Регрессии: на каждый исправленный баг — тест, который падал до исправления.
- Контракты: поведение экспортируемого API и инварианты конкурентности.
- Критические пользовательские сценарии — интеграционно, если это возможно без сети и GPU.

## Что не тестировать

- Пиксели и точную раскладку Qt. Для UI — ручной сценарий.
- Тривиальные геттеры, сеттеры, теги структур и сгенерированный код.
- Поведение стандартной библиотеки.
- Приватные детали реализации. Тестируй через экспортируемый API.
- Каждую ветку ради покрытия. Целевого процента нет.
- Живые сайты и сеть в обычных unit-тестах.

## Форма теста

- Табличный тест — для вариантов одного поведения. Один тест — одно утверждение о поведении.
- Имена `t.Run` описывают сценарий: `empty history`, `cancelled context`.
- Arrange — act — assert. Без логики и условий в тесте.
- `t.TempDir()` и `t.Cleanup()`; никаких записей в репозиторий.
- Никаких `time.Sleep`. Каналы, фейковые часы, явные события.
- `t.Parallel()` — только для независимых тестов без общих изменяемых данных.
- Случайность проверяй на инвариант (диапазон, допустимость), а не на попадание всех значений: тест не должен зависеть от броска кубика.
- Golden-файлы — только для большого стабильного вывода. Обновление — осознанно, с просмотром diff.
- Тест лежит рядом с кодом, `_test.go`. `package foo_test` — когда проверяется только публичный API.
- Хелперы — в `_test.go`, с `t.Helper()`.

## Фейки

- Сначала реальная реализация с `t.TempDir()` или SQLite в памяти.
- Интерфейс создаётся только если он нужен потребителю. Фейк живёт в `_test.go` потребителя.
- Без mock-фреймворков и сгенерированных моков.
- Фейк записывает вызовы и возвращает заданные ошибки. Он не повторяет бизнес-логику.
- `catalog`-значения конструируются напрямую, а не через фейковый источник.

## Интеграционные тесты

- По умолчанию `go test ./...` не ходит в сеть, не запускает mpv, Chromium и установщики.
- Включаются переменной `YO_INTEGRATION=1`. Без неё — `t.Skip` с причиной.
- Тест, которому нужен внешний компонент, проверяет его наличие и скипается с понятным сообщением.
- Сеть — только против локального сервера или записанных фикстур. Живой сайт — вручную.
- БД — реальный SQLite в `t.TempDir()` с теми же миграциями. Не подменяй SQL фейком.
- Для UI и плеера — ручной чек-лист: шаги, ожидаемый результат, фактический результат.

## Команды

```powershell
go test ./...
go test -race ./...
go test ./core/store -run TestHistory -v
go vet ./...
```

- Во время работы гоняй тесты пакета, перед сдачей — весь набор.
- Менялись конкурентные участки — `go test -race ./...` обязателен.
- Если тест нельзя запустить, скажи почему. Не выдумывай «все зелёные».

## Данные

- Фикстуры — в `testdata/`, маленькие и обезличенные.
- Никаких реальных имён, домашних путей, логинов, e-mail, cookies, токенов и секретов в репозитории. Только нейтральные заглушки вроде `example`, `C:\Users\example`. Вычищай перед коммитом.
- HTML-фикстура источника — минимальный фрагмент; в комментарии источник и дата записи.
- Большие медиафайлы не коммить. Для них — путь в переменной окружения.
