# Код

## Бюджеты

- пакет: ≤ 15 файлов и ≤ 2 500 строк;
- файл: ≤ 500 строк, ≤ 600 для сложного экрана;
- функция: ≤ 80 строк;
- `root`: ≤ 600 строк.

Бюджет — сигнал, что ответственность пора делить. Не прячь код в одну длинную функцию и не дроби на десять файлов по 20 строк.

## Пакеты

- Пакет — одна причина меняться. Имя — существительное предметной области: `playback`, `history`, `update`.
- Запрещены имена-заглушки: `util`, `common`, `helpers`, `misc`, `models`, `types`, `interfaces`, `base`.
- Не создавай `internal/`. Границы заданы верхнеуровневыми модулями.
- У каждого пакета — комментарий-контракт до 20 строк: назначение, импорты, запреты, инварианты. Комментарий пакета живёт в `doc.go`. Если нужно больше, остановись и объясни, почему; пиши по делу, без воды.
- Файлы называются по теме (`history.go`, `migrations.go`), а не по слою (`helpers.go`, `types.go`).
- Никаких `init()` и пакетных изменяемых переменных. Константы и чистые функции — можно.
- Пакет не хранит глобальный логгер, HTTP-клиент, БД или конфиг. Всё приходит в конструкторе или через `*Options`.

## Файлы и функции

- Один файл — одна тема. Если файл начинается с «разное», его нужно делить.
- Функция делает одно действие. Больше 80 строк — дели.
- Ранние возвраты вместо вложенных `if`. Глубина вложенности — не больше трёх.
- 4–5 параметров — ориентир, а не закон. Больше — сигнал сгруппировать связанные значения в приватный тип, а не механически дробить функцию.
- Boolean-параметр допустим, если он задаёт один понятный режим приватного помощника. Если флагов больше одного или они меняют смысл, разведи методы или опции.
- Не прячь ошибку в `nil`-ветку. Явный `if err != nil` на границе.
- Цикл не должен содержать бизнес-правил на 40 строк. Вынеси тело.

## Абстракции

- Сначала конкретный тип. Интерфейс — только когда он реально нужен.
- Интерфейс объявляет потребитель, в своём пакете, 1–3 метода. Провайдер отдаёт конкретный тип.
- Не создавай интерфейс «для тестов», если тест может работать с реальным типом и `t.TempDir()`.
- Запрещены DI-контейнеры, service locator, глобальные реестры, generic repository и unit of work.
- Не делай обёртку, которая только пересылает вызовы. Это лишний слой.
- Не добавляй опции, поля и хуки «на будущее». Появятся требования — появятся поля.
- Один DTO — один владелец. `catalog` — единственный общий набор моделей; не дублируй его в `core`.

## Владение данными

- У изменяемого состояния один владелец. UI-состояние — на UI-горутине; состояние предметной области — в своём пакете.
- Через границы передавай значения или неизменяемые снимки. Не раздавай указатели на общие map и slice.
- `catalog`-типы — DTO. Если сохраняешь их надолго, копируй, а не держи ссылку на чужое состояние.
- Строки БД — приватные для `core/store`. Наружу отдаются `catalog`-типы, преобразование — на границе.
- Время в хранилище — UTC. Локальное время — только для показа.
- Не возвращай внутренние слайсы и map напрямую. Копия или итератор.
- `nil` и пустая коллекция — разные вещи. Для UI и JSON предпочитай пустой слайс; документируй исключения.

## Ошибки

- Ошибки возвращаются, а не печатаются. `panic` — только для нарушенного инварианта при старте.
- Оборачивай с контекстом: `fmt.Errorf("load history: %w", err)`.
- Для решений вызывающего — sentinel-ошибки и `errors.Is` / `errors.As`. Свои типы ошибок — только если нужны поля.
- Текст ошибки: строчные буквы, без точки, без «failed to». `open database: permission denied`.
- Не логируй и не возвращай одновременно. Логирует граница, возвращает слой.
- Пользовательский текст ошибки формирует UI. Ошибки `core` — технические.
- Уважай отмену: проверяй `ctx.Err()` и возвращай её, не подменяй своей.
- Не сравнивай текст ошибки строками.

## Конкурентность

- У каждой горутины есть владелец и условие остановки. Запуск «в никуда» запрещён.
- Не запускай горутины в `Layout`, конструкторе-геттере и в цикле на каждую строку.
- `context.Context` — первый параметр I/O; не храни его в структуре.
- Канал закрывает владелец. Буфер — только с объяснением, зачем.
- Мьютекс защищает инвариант, а не отдельное поле. В комментарии укажи, что именно.
- `sync.Mutex` по умолчанию; `RWMutex` — только после измерения.
- Никаких `time.Sleep` для синхронизации. Каналы, `context`, `sync.Cond` или явные события.
- Колбэки: документируй, в какой горутине выполняются. UI-колбэки — только на UI-горутине.
- Менялись конкурентные участки — гоняй `go test -race`.

## Логирование

- Логгер приходит в конструкторе или через `*Options` и хранится в поле. Никаких пакетных логгеров и `slog.Default()`.
- Уровни: `debug` — поток, `info` — lifecycle, `warn` — восстановимая проблема, `error` — операция провалена.
- Логируй старт и конец внешних операций, ошибки и смену состояния. Не логируй кадры и каждую строку.
- Запрещены секреты, токены, cookies, пароли, полные URL с query и пользовательский текст.
- Одна ошибка логируется один раз, на границе. Не дублируй в каждом слое.

## Комментарии

- Комментарий пакета — контракт до 20 строк в `doc.go`: что делает, что импортирует, что запрещено, какие инварианты. Если нужно больше, остановись и объясни, почему; пиши по делу, без воды.
- Переноси строки комментария по смыслу: ориентир — до 100 символов. Не склеивай контракт в одну длинную строку; `gofmt` комментарии не переносит.
- Экспортируемое документируется и начинается с имени.
- Комментарий объясняет «почему», ограничения, владение, горутину и единицы измерения. Не пересказывай код.
- Запрещены закомментированный код, история изменений и «TODO» без имени и причины.
- Код и идентификаторы — по-английски. Документация — по-русски.

## Имена и стиль

- Стандартный Go: `MixedCaps`, короткие локальные имена, описательные экспортируемые.
- Аббревиатуры — заглавными: `ID`, `URL`, `HTTP`, `SQL`, `API`.
- Без заикания: `playback.Session`, а не `playback.PlaybackSession`. Исключение — значение, чьё имя естественно совпадает с пакетом: `appearance.Appearance`, `shell.Shell`, `navigator.Navigator`. Это осознанное исключение, а не повод для новых имён-близнецов.
- Без `Get`: `History()`, а не `GetHistory()`.
- Файлы — строчные, без подчёркиваний, кроме `_windows.go`, `_other.go`, `_test.go`.
- Импорты группируются: std, внешние, локальные. `gofmt` обязателен.
- Без dot-import. Пустой импорт — только для `//go:embed` и подобных директив.
- Магические числа запрещены: константа с единицей (`30 * time.Second`, `8 * gtx.Dp`).
- Длительности — `time.Duration`, не `int` секунд. Размеры — явные единицы.
- `fmt.Println` в коде приложения запрещён: логгер или UI.

## Зависимости

- Сначала стандартная библиотека.
- Потом уже подключённые зависимости из `go.mod`.
- Если нужна новая — найди подходящую библиотеку, проверь активность, лицензию и размер, предложи пользователю. Добавляй только после согласования.
- Не тяни библиотеку ради одной функции.
- CGO — только если этого требует платформа; изменение условий сборки фиксируй в отчёте.
