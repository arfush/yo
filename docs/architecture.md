# Архитектура Yonime

Документ фиксирует целевую структуру пакетов и направления зависимостей.
Правила, которые уже можно проверить, закреплены тестом
`tools/architecture/architecture_test.go`; он входит в обычный `go test ./...`.

## Принципы

- **Фича важнее слоя.** Пакет называется по задаче (`library`, `playback`,
  `party`), а не по техническому слою (`domain`, `infrastructure`).
- **`internal/` не используется.** Внутренние пакеты и так недоступны снаружи
  модуля, а лишний уровень в пути только удлиняет импорты. Ограничения
  задаются правилами зависимостей, а не расположением каталога.
- **`cmd/` — только точки входа.** В `cmd` нет логики, которую можно
  переиспользовать или протестировать отдельно.
- **`app` — композиционный корень.** Он знает про все сервисы и экраны,
  собирает их и передаёт экранам данные и команды. Экраны не создают сервисы
  сами.
- **Пакет-фича не знает про UI.** `library`, `playback`, `store` и остальные
  возвращают данные и ошибки; показывать их — задача `ui`.
- **`platform` — только механизм ОС.** Пути `%APPDATA%`, реестр, мьютекс
  одного экземпляра, трей и Win32-заголовок окна. Никакой продуктовой
  политики.

## Целевое дерево

```text
cmd/
  yonime/            single instance, установка обновления, запуск ui
  watchplay/         консольный клиент комнаты для проверки протокола
app/                 композиционный корень: сервисы, экраны, команды
catalog/             чистые типы: Title, Episode, Voice, UserStatus
animelib/            API AnimeLIB, rate limit, прямые ссылки на серии
browser/             Playwright: Chromium, авторизация, headless Kodik
kodik/               резолв Kodik embed -> HLS
library/             загрузка тайтла, выбор озвучки/серии, обложки
metadata/            Shikimori/MAL, AniList, IMDb, introdb
mpv/                 поиск и установка mpv
playback/            сессия mpv, очередь, прогресс, главы, автопропуск
party/               протокол совместного просмотра, часы, конфигурация реле
store/               SQLite: схема, история, настройки, кэши
token/               файл токена AnimeLIB и проверка срока
updates/             GitHub Releases, версия, SHA-256
updater/             подмена запущенного exe (фича, не примитив ОС)
log/                 журнал приложения и кольцевой буфер
version/             версия по умолчанию и форматирование
platform/
  appdata/           пути в %APPDATA%\Yonime
  install/           проверка установки через реестр Windows
  singleinstance/    один запущенный экземпляр на пользователя
  tray/              значок и меню в системном трее
  window/            Win32: кастомный заголовок, DWM, DPI
ui/
  kit/               примитивы раскладки, общие для экранов
  controls/          переиспользуемые кнопки, карточки, строки (состав
                     определяется отдельно; пока не выносить)
  chrome/            заголовок окна, футер, полоса ошибки
  screen/            экраны: home, title, settings, party, log, shortcuts,
                     firstrun, token
  theme/             цвета, типографика
  icons/             iconvg-ассеты и их embed
  assets/            шрифты, маскот
docs/
deploy/
installer/
third_party/
tools/
```

`ui/controls` пока пустой по смыслу: состав переиспользуемых элементов ещё не
согласован. Не добавляй туда новые дизайны «на будущее».

## Направления зависимостей

Стрелка `A -> B` означает «A может импортировать B».

```text
cmd -> app, все фичи, platform
app -> ui, все фичи, platform, log, version, catalog
ui  -> catalog, log, version, party (типы протокола)
фичи -> catalog, log, version, token, platform
platform -> log, version
log, version, token, catalog -> только стандартная библиотека
```

Запрещено:

- импортировать `cmd/...` — это точки входа;
- импортировать `ui` из чего угодно, кроме `app` и `cmd`;
- импортировать `app` из `ui` и фич;
- импортировать `store` из `ui`: экран получает данные через `app`;
- импортировать фичи (`library`, `playback`, `party`, ...) из `platform`;
- замыкать импорты в цикл.

Тест проверяет эти правила для production-файлов; тестовые файлы в граф не
входят, чтобы тест одного пакета мог свободно собирать чужие пакеты.

## Почему так

### `updater` не в `platform`

`platform` — это тонкие обёртки над ОС без продуктовой логики. В `updater`
продуктовая логика и есть: проверить цель, подготовить `update-helper.cmd`,
дождаться выхода процесса, заменить файл, убрать временные файлы. От ОС там
зависит только запуск скрытого `cmd.exe` (и заглушка для других ОС).

Если считать признаком платформенности наличие файла `*_windows.go`, то в
`platform` пришлось бы отправить ещё `mpv` (скачивание Windows-сборки),
`browser` (Playwright/Chromium), `install` и `tray`. Тогда `platform`
перестанет означать «механизм ОС» и станет свалкой. Поэтому `updater`
остаётся отдельной фичей; при необходимости из него можно выделить
`platform/replace` для одного запуска, но сейчас это преждевременно.

### `token` — это файл токена AnimeLIB

Пакет читает и пишет `%APPDATA%\Yonime\animelib_token.txt`: JSON-объект
OAuth-токена (как в localStorage сайта), запечатанный пользовательским Windows
DPAPI, плюс запасной разбор простой строки. Старый открытый файл читается и
переписывается в DPAPI-контейнер при первом `Load`. Пакет проверяет срок с
запасом `ExpiryMargin` в 2 минуты.

Пакет нужен двум независимым сторонам: `browser` сохраняет токен после входа,
`library` читает его для API. Если положить токен в `browser`, то `library`
начнёт зависеть от Playwright; если в `animelib`, то `browser` начнёт зависеть
от API-клиента и его rate limiter. Отдельный маленький пакет — самый дешёвый
способ разорвать эту связь.

### `version` и `updates`

`version` — форматирование и версия по умолчанию, без сети. `updates` —
проверка GitHub Releases и скачивание, то есть фича. Не смешивай их:
`platform/install` и `ui` могут знать про `version`, но не про `updates`.

## Совместимость имён

Переименование пакета не должно ломать данные и релизный процесс. Файл
конфигурации реле теперь называется `%APPDATA%\Yonime\party.json`; старый
`watchparty.json` переносится при первом запуске. Сознательно оставлены без
изменений только контракты, которые нельзя мигрировать автоматически:

- переменные `WATCHPARTY_CLOUDFLARE_URL`, `WATCHPARTY_SUPABASE_URL`,
  `WATCHPARTY_SUPABASE_KEY` и одноимённые repository variables;
- настройки `party_provider` и `party_name` в SQLite (они уже были `party_*`).

Остальные имена переведены в пространство `party`: адрес комнаты
`sha256("yonime/party/room\x00" + ключ)`, метка карточки `yonime/party/card` и
тема Supabase `realtime:party:`. Это протокол `3.0`: комната, открытая старой
версией, новому клиенту не видна, поэтому обновлять нужно обе стороны. Реле
перевыпускается вместе с такой сменой.
