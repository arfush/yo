# UI

## Граница

`ui` только показывает и принимает ввод. Внутри нет HTTP, SQL, парсинга, файловых операций и бизнес-правил.

- Экран получает готовые данные и колбэки. Запросы идут через API `core`, а не через UI-код.
- Состояние предметной области меняется через API `core`. UI не мутирует объекты, которыми владеет `core`.
- UI-состояние — фокус, скролл, наведение, черновик формы — живёт в структуре экрана на UI-горутине.
- Сборку зависимостей делает `root`. Навигацией владеет `ui/navigator`, а не экран и не `root`.

## Qt: жизненный цикл отрисовки

- `Paint(p *qt6.QPainter, content image.Rectangle, palette appearance.Palette)` вызывается на каждую отрисовку кадра. В нём нельзя блокироваться, ждать, спать, читать файлы, ходить в сеть и запускать горутины.
- Экран раскладывает элементы виджетами `ui/kit` на переданном painter в границах `content`. Раскладку и позиции считай от этого прямоугольника, а не от размера окна.
- Состояние экрана — фокус, скролл, наведение, черновик формы — хранится в структуре экрана на UI-горутине.
- Не создавай большие слайсы и map на каждый кадр. Кэшируй вычисления, которые зависят только от данных.
- Длинные списки рисуй по видимой области, а не «построить все строки».
- Анимация считается от времени, а не от номера кадра. Пока анимация активна — запрашивай перерисовку.
- Перерисовку запрашивай через `QWidget.Update()` на UI-горутине. Из другой горутины не трогай виджеты; результат передай в UI-горутину.
- Не дублируй hit testing. Указатель и колесо приходят в экран из shell; экран сам решает, что нажато.
- Нативный ввод — через виджет Qt (`QLineEdit`), а не самописный редактор. Рамку вокруг него даёт виджет из `ui/kit`.
- Иконка без текста обязана иметь подпись для доступности. Основные действия должны быть доступны с клавиатуры.
- Текст рисуется шрифтом из `ui/appearance`, а не системным шрифтом, выбранным на месте.

## Appearance и ресурсы

- Цвета, отступы, радиусы, размеры шрифтов и длительности — только из `ui/appearance`. Литералы в экранах запрещены.
- Токены семантические: `Surface`, `Danger`, `TextMuted`, а не `Red` и `Gray2`.
- Язык — состояние `ui/appearance`. Строки — из `ui/resource` через `ui/appearance`; литералы в экранах запрещены.
- Смена языка обновляет строки и форматирование без перезапуска.
- `ui/resource` хранит встроенные ассеты: иконки, шрифты, изображения, строки. Они встраиваются через `//go:embed`, декодируются один раз при старте и кэшируются.
- Векторные иконки отдаются как готовые `*qt6.QPainterPath` в сетке `resource.IconBox`; путь принадлежит `ui/resource` и только тонируется при отрисовке.
- `ui/appearance` может импортировать `ui/resource`; обратное запрещено.
- В `Paint` нельзя читать файлы, декодировать картинки и создавать шрифты.
- Размеры — в логических пикселях; масштаб экрана применяет Qt. Сырые пиксели устройства запрещены.
- Новые палитры, языки и наборы ресурсов не добавляются без задачи.

## Виджеты

- Все элементы экрана рисуются виджетами `ui/kit`.
- Метод отрисовки называется `Paint`, не `Draw`: и у экранов, и у виджетов `ui/kit`.
- Экран не рисует элементы сам: он только раскладывает виджеты и передаёт им данные и состояние.
- Новый элемент появляется в `ui/kit`, а не в `ui/screen`.
- Если задача требует отрисовать сложный элемент, а пользователь не назвал виджет `ui/kit`, остановись и спроси.
- `ui/kit` — набор функций и типов, а не фреймворк. Никаких плагинов, реестров виджетов и вариантов «на будущее».
- Не оборачивай стандартный виджет Qt в обёртку, которая только меняет один отступ. Параметр `ui/appearance` дешевле.

## Экраны

- Все экраны живут в пакете `ui/screen`; подпакетов нет.
- Одна фича — файлы `<feature>*.go`.
- `<feature>.go` — структура экрана, конструктор, состояние, зависимости, обработчики, интенты и `Paint`.
- `Paint` ничего не рисует сам: он раскладывает элементы виджетами `ui/kit`.
- Публичный API пакета — только типы экранов, конструкторы и `Paint`. Других экспортируемых методов нет.
- Виджеты в экране не объявляются: все элементы — из `ui/kit`.
- `Paint` разбит на секции и приватные методы. Файлы экрана — до 600 строк каждый.
- Экран не импортирует другой экран. Переход — через интент `ui/navigator`.
- Глобальных синглтонов нет. Зависимости передаёт `root`.
- Загрузка, ошибка и пустое состояние — часть экрана. Пустое окно без объяснения запрещено.
- Долгая операция показывает состояние и даёт отменить или уйти, если это возможно.
- Разрушительное действие требует подтверждения.
- У каждого экрана есть понятный путь назад.

## Навигация

- `ui/navigator` владеет навигацией: `Navigate()`, интенты, `Handler`, стек экранов, переходы.
- `ui/navigator` импортирует `ui/shell` и вызывает его для заголовка и notice.
- `root` создаёт экраны и передаёт в `navigator` колбэки-фабрики для их создания при сборке. Типы фабрик живут в `ui/navigator/factory.go`, конкретные методы создания — в `root/screen.go`.
- `navigator.Navigate()` решает, какой экран выбрать и когда вызвать фабрику. Пакеты экранов `navigator` не импортирует.
- `ui/shell` не импортирует `navigator`, экраны и `root`; его события передаются колбэками.
- Интент описывает намерение и параметры, а не конкретный тип экрана.
- Экран сообщает о переходе через колбэк или `Handler`; сам стек не пушит.
- Экран не импортирует `root` и `shell`.
- `Navigate()` только ставит интент в очередь и просит перерисовку. Стек меняет `Apply()` до ближайшей отрисовки. Поэтому вызов `Navigate()` из обработки события безопасен: навигация не выполняется посреди отрисовки.
- Назад — одно предсказуемое поведение, заданное в `ui/navigator` или задаче. Не изобретай разные правила для экранов.

## Платформенные файлы

- Windows-код — в `_windows.go`, остальное — в `_other.go` с `//go:build !windows`.
- Общий код обязан компилироваться на не-Windows, даже если функция — заглушка.
- Win32, трей, диалоги, буфер обмена и single instance — через `core/platform`, не напрямую из `ui`.
- Платформенные пути — только конкретные (`JournalPath`), без общих `AppData`-хелперов.
- Build tags — только для платформ. Не включай фичи тегами.
- Платформенный файл не содержит бизнес-логики и не дублирует общий код.

## Текст

- Пользовательские строки — из `ui/appearance`/`ui/resource`, не литералами в экранах.
- Бренды и названия провайдеров не переводятся.
- Числа, даты и длительности форматируются общими помощниками из `ui/appearance`, а не в каждом экране.
- В поставляемом UI не должно быть lorem ipsum и заглушек вроде «TODO: текст».
