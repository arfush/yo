# Совместный просмотр

Две и более копии Yonime смотрят один тайтл синхронно. Создатель комнаты
(хост) — источник истины, остальные (гости) подстраиваются под его позицию.

Сервера у проекта нет: реле разворачивается один раз автором сборки на
бесплатном плане Cloudflare или Supabase и вшивается в exe. Пользователю
ничего настраивать не нужно — ни файлов, ни ключей. Инструкции для того, кто
разворачивает реле, лежат в `deploy/cloudflare` и `deploy/supabase`.

## Пользовательский сценарий

1. Кнопка с двумя человечками в футере главного экрана открывает форму
   «Совместный просмотр».
2. Переключатель провайдера (`Cloudflare` / `Supabase`) выбирает реле. Он
   переключается только в том случае, если в сборку вшиты оба реле; при одном
   реле рядом с заголовком просто написано его имя.
3. **Создать** выдаёт ключ из 9 латинских букв, всегда начинающийся с `YO`,
   например `YOFBQOPGZ`. Ключ копируется круглой кнопкой.
4. **Присоединиться** принимает ключ в любом регистре; поле само приводит его к
   верхнему регистру и отбрасывает посторонние символы.
5. Пока хост не запустил тайтл, гость видит кошкодевочку и подпись «Ожидаем
   создателя комнаты».
6. Как только хост запускает серию, у гостей открывается mpv на той же секунде.

`Esc` и кнопка «Вернуться» уводят на главный экран, но комнату не закрывают:
кнопка совместного просмотра начинает тускло светиться зелёным, а повторное
нажатие открывает ту же форму с тем же ключом. Закрывает комнату только
«Удалить комнату».

## Модель синхронизации

Ключевая идея: по сети ходит **якорь**, а не поток позиций.

```go
type State struct {
    TitleSlug    string
    Voice        string
    Episode      string
    EpisodeIndex int
    Playing      bool
    Position     float64 // секунды
    Anchor       int64   // часы хоста, unix ms
}
```

- Позиция считается функцией от времени: `PositionAt(hostNow)`.
- Потерянный пакет ничего не ломает: следующий якорь всё исправит, а до него
  гость экстраполирует сам.
- Хост публикует якорь раз в 4 секунды во время воспроизведения и раз в 10
  секунд на паузе. Дополнительно — сразу после паузы, смены серии и
  обнаруженной перемотки (сравнение фактической позиции с ожидаемой).

### Часы

Участники не обмениваются ping/pong. Каждый входящий якорь уже содержит время
хоста, а локальное время получения известно, поэтому

```text
delta = local_recv - anchor_host
offset = -min(delta по последним 96 якорям)
```

Минимум отбрасывает сетевые всплески: чем быстрее пришёл пакет, тем точнее
оценка. Систематическая ошибка — минимальная сетевая задержка (десятки
миллисекунд), она одинакова у всех гостей и не накапливается.

### Коррекция расхождения

Раз в секунду гость сравнивает свою позицию с ожидаемой:

| Расхождение | Действие |
| ----------- | -------- |
| < 220 мс | ничего, скорость 1.0 |
| 220 мс – 900 мс | плавная правка скорости в диапазоне `0.94–1.06` |
| > 900 мс | точный seek на `ожидаемая + 0.15` |

Небольшой «перелёт» при seek компенсирует время, которое команда идёт до mpv.
mpv запускается с `--hr-seek=yes`, иначе seek округлялся бы до ключевого кадра.

Пауза хоста передаётся как `Playing: false` с фиксированной позицией: гости
ставят mpv на паузу, а не догоняют её.

## Протокол

Один и тот же JSON в обе стороны, поверх WebSocket:

| Сообщение | Кто шлёт | Смысл |
| --------- | -------- | ----- |
| `{"t":"hello"}` | гость | «пришли свежий якорь» |
| `{"t":"state","state":{...}}` | хост | новый якорь |
| `{"t":"welcome","host":true}` | реле | создатель в комнате |
| `{"t":"bye"}` | хост/реле | создатель ушёл |
| `{"t":"error","error":"..."}` | реле | отказ |

Важная деталь: хост публикует якорь сразу после подключения, даже если ещё
ничего не запустил (`Started() == false`). Для гостя это доказательство, что
комната существует. Если за 12 секунд ни одного признака хоста не пришло,
гость возвращается к форме входа с ошибкой «Комната не найдена — проверьте
ключ».

### Cloudflare

`GET /room?key=YOFBQOPGZ&role=host|guest` апгрейдится до WebSocket. Worker
выбирает Durable Object по ключу (`idFromName`), объект хранит сокет хоста,
множество гостей и последний якорь. Комната живёт, пока открыт хотя бы один
сокет.

### Supabase

Клиент подключается к `/realtime/v1/websocket` по протоколу Phoenix и входит в
канал `realtime:watchparty:<КЛЮЧ>` с `broadcast: {ack: false, self: false}`.
Сообщения комнаты — это broadcast-события `msg`, heartbeat — раз в 25 секунд.
Ни таблиц, ни RLS, ни edge-функций.

## Расход квот

Дизайн рассчитан на бесплатные тарифы.

**Supabase** считает доставленные сообщения, лимит — 2 млн в месяц. При
просмотре 4 часа в день и 10 участниках получается около 1,1 млн: хост шлёт
один якорь раз в 4 секунды (900 в час), каждый гость получает его один раз.
Отдельного трафика от гостей нет, кроме редких `hello`. Если проект один на
всех пользователей сборки, квота общая: её хватает примерно на 37
часов просмотра в сутки суммарно. Поэтому основным реле выбран Cloudflare, а
Supabase удобен как резерв или собственный проект.

**Cloudflare**: запрос считается на подключение сокета, а не на сообщение.
100 000 запросов в день — это десятки тысяч переподключений.

## Настройка

Официальная сборка уже содержит адрес реле: комнаты работают сразу после
установки. Адреса передаются при сборке через `-ldflags -X` и берутся из
переменных окружения, поэтому реле разворачивается один раз:

| Переменная | Символ в ldflags |
| ---------- | ---------------- |
| `WATCHPARTY_CLOUDFLARE_URL` | `watchparty.CloudflareURL` |
| `WATCHPARTY_SUPABASE_URL` | `watchparty.SupabaseURL` |
| `WATCHPARTY_SUPABASE_KEY` | `watchparty.SupabaseKey` |

`build.ps1` подставляет всё, что нашёл в окружении, а релизный workflow —
значения одноимённых repository variables. Если переменных нет, значения
берутся из `watchplay.json` в корне репозитория (`cloudflare_url`,
`supabase_url`, `supabase_key`). Там лежат образцы, и сборка намеренно их
пропускает: иначе пользователи получили бы нерабочее реле. Сборка никогда не
перезаписывает `watchplay.json`.

Приоритет: переменная окружения → `watchplay.json` → «провайдер не настроен».

Для публичной сборки достаточно одного Cloudflare: у него нет ключа, и он не
делит квоту сообщений между всеми пользователями.

`%APPDATA%\yonime\watchparty.json` (образец — `deploy/watchparty.example.json`)
остаётся только для тех, кто собирает из исходников или подключает своё реле:
любое заполненное поле перекрывает вшитое значение. Пустое поле означает
«провайдер не настроен»: кнопка покажет это текстом, приложение не упадёт.

Для Supabase нужен **publishable** ключ (`sb_publishable_...`; в старых
проектах — `anon`). Секретный ключ (`sb_secret_...`, `service_role`) в сборку
попасть не должен: он обходит RLS, а для Realtime с публичными каналами не
нужен.

## Консольный клиент

Для проверки синхронизации без интерфейса есть `cmd/watchplay`. Он использует
тот же `internal/playback` и то же реле, что и приложение:

```powershell
go run ./cmd/watchplay create solo-leveling "AniLibria" 1
go run ./cmd/watchplay open YOFBQOPGZ
```

`create` печатает ключ комнаты, запускает mpv и публикует якоря. `open`
подключается гостем, ждёт создателя, открывает ту же серию и подстраивается под
его позицию. Во время работы принимаются команды:

| Команда | Действие |
| ------- | -------- |
| `pause` / `play` | пауза и продолжение (только у создателя) |
| `seek <сек>` | точная перемотка; `seek +30` и `seek -15` — относительно текущей позиции |
| `status` | позиция mpv, якорь хоста и расхождение в секундах |
| `reopen` | гость заново открывает свой mpv на текущей серии, если закрыл окно |
| `quit` | выйти из комнаты |

Окно mpv у клиента подписано ролью: «Yonime — создатель» или «Yonime —
гость». Это важно, когда оба клиента запущены на одном компьютере: два
одинаковых окна легко перепутать, и закрытое окно гостя выглядит как
«плеер не закрывался», если рядом осталось окно создателя. Учтите также, что
mpv по умолчанию закрывается по `Esc` и `q`, когда его окно в фокусе.

Флаг `-provider cloudflare|supabase` ставится перед командой. Настройки клиент
берёт из `%APPDATA%\yonime\watchparty.json` или из `watchplay.json` рядом с
бинарником; образцы из репозитория он пропускает.

## Диагностика

| Симптом | Причина |
| ------- | ------- |
| «Cloudflare не настроен» | в сборке нет `cloudflare_url` и нет `watchparty.json` |
| «По адресу реле работает не комната (ответ 200)» | Worker задеплоен, но в нём шаблон Hello World: задеплойте `deploy/cloudflare` и проверьте `/health` (должно быть `ok`) |
| «Supabase не настроен» | нужны и URL, и publishable-ключ |
| «Комната не найдена» | ключ с опечаткой либо создатель ещё не подключился |
| Гость отстаёт на секунды | хост на паузе; проверьте, идёт ли воспроизведение |
| Постоянные переподключения | провайдер режет `workers.dev` — переключитесь на Supabase |
| Гость стартует не с той серии | у хоста другая озвучка: серия берётся из его состояния |

## Известные ограничения

- Одна комната на запущенный экземпляр Yonime.
- Публичное подключение Supabase Realtime живёт не дольше 24 часов; клиент
  переподключается сам и продолжает с последнего якоря.
- Гость не может управлять воспроизведением: перемотка и пауза — только у
  создателя. Это осознанно, иначе состояние комнаты пришлось бы согласовывать.
- Прямой плеер AnimeLIB и Kodik — разные таймлайны. Если у хоста серия идёт
  через Kodik, а у гостя через прямой плеер (или наоборот), расхождение может
  оказаться больше обычного: скорость и seek это исправят, но с заметным
  рывком в начале.
