# Совместный просмотр через Cloudflare

Реле — Worker + Durable Object. Одна комната = один Durable Object, которому
клиент отдаёт не ключ, а его адрес: `sha256("yonime/party/room\0" + ключ)`,
первые 16 байт в hex (32 символа). Ключ вида `YOC4K7Q2M` (буква `C` после `YO`
означает Cloudflare) остаётся у собеседников. Сайт `*.workers.dev` работает на
бесплатном плане, отдельный домен не нужен.

## Что понадобится

- аккаунт Cloudflare (бесплатного плана достаточно);
- Node.js 18+ и `npm`;
- около двух минут.

## Деплой

```bash
cd deploy/cloudflare
npm install -g wrangler     # если wrangler ещё не установлен
wrangler login
wrangler deploy
```

`wrangler deploy` напечатает адрес вида:

```text
https://yonime-party.<ваш-аккаунт>.workers.dev
```

Проверка, что реле живо:

```bash
curl https://yonime-party.<ваш-аккаунт>.workers.dev/health
# ok
```

Если вместо `ok` приходит `Hello World!`, значит на этом адресе всё ещё
стандартный шаблон Worker: выполните `wrangler deploy` из `deploy/cloudflare`
и проверьте снова. Приложение в таком случае показывает ошибку «по адресу реле
работает не комната (ответ 200)».

## Как это попадает к пользователям

Реле разворачивается **один раз**, а его адрес вшивается в сборку: пользователи
получают exe, в котором комнату можно создать без единого файла настроек и без
ключей. Порядок для автора сборки:

1. `wrangler deploy` — получить адрес.
2. Проверить `/health`.
3. Записать адрес в один из двух источников:
   - переменная `WATCHPARTY_CLOUDFLARE_URL` (локально — в окружении, в CI —
     GitHub **Settings → Secrets and variables → Actions → Variables**);
   - или `cloudflare_url` в `watchplay.json` в корне репозитория.
4. Собрать релиз (`release: vX.Y`). `build.ps1` передаёт значение в
   `-ldflags -X party.CloudflareURL`, поэтому все три архитектуры выйдут с
   уже подключённым реле.

Переменная окружения важнее файла: если она задана, `watchplay.json` не
используется и не меняется. Образцы (`example.workers.dev`) сборка пропускает и
предупреждает об этом — так релиз не уедет с нерабочим реле.

Локальная сборка:

```powershell
$env:WATCHPARTY_CLOUDFLARE_URL = "https://yonime-party.<ваш-аккаунт>.workers.dev"
.\build.ps1 -Version 1.0 -Arch amd64
```

Адрес не секретный: он виден в exe и в трафике. Подменять его на этапе
эксплуатации не нужно — новые адреса приезжают с обновлением приложения.

## Подключение клиента без своей сборки

Адрес можно ввести в настройках Yonime: **Совместный просмотр → Провайдер →
Cloudflare Endpoint**. То же самое можно сделать файлом
`%APPDATA%\Yonime\party.json`:

```json
{
  "cloudflare_url": "https://yonime-party.<ваш-аккаунт>.workers.dev"
}
```

`https://` писать можно: клиент сам переводит адрес в `wss://`. Файл перекрывает
вшитое значение. Провайдер **Cloudflare** выбирается в блоке настроек; в форме
комнаты провайдер не выбирается: ключ с буквой `C` сам приведёт гостя на это
реле.

Вшить адрес вручную тоже можно:

```bash
go build -ldflags "-X github.com/arfush/yonime/party.CloudflareURL=https://yonime-party.example.workers.dev" ./cmd/yonime
```

## Что внутри

| Файл             | Назначение                                        |
| ---------------- | ------------------------------------------------- |
| `src/worker.js`  | Worker: маршрут `/room` и класс `Room`            |
| `wrangler.toml`  | биндинг `ROOMS` и миграция Durable Object         |

Worker:

1. проверяет адрес (`/^[0-9a-f]{32}$/`) и роль;
2. выбирает Durable Object по адресу через `idFromName`;
3. передаёт апгрейд сокета объекту.

Ключ комнаты, секрет и содержимое комнаты Worker не видит. Карточка комнаты
(закрыта ли она, номер поколения, соль) передаётся в открытом виде, потому что
по ней гость понимает, нужен ли секрет; якоря и команды — это AES-GCM
шифротекст.

Durable Object:

- держит сокет создателя комнаты и множество гостей;
- запоминает карточку и последний зашифрованный `state` и отправляет их новому
  гостю;
- на `hello` от гостя просит создателя прислать свежие карточку и `state`,
  чтобы гость не ждал следующего heartbeat и сразу узнал про секрет;
- пересылает `control` только создателю;
- при уходе создателя чистит карточку и якорь и рассылает гостям `bye`.

## Ограничения бесплатного плана

- 100 000 запросов в день. Комната тратит один запрос на сокет, дальше это
  обычные сообщения WebSocket, а не новые запросы.
- 13 000 ГБ·с в день для Durable Objects: одна комната на 4 часа занимает
  несколько ГБ·с, так что запас огромный.
- Соединения к `workers.dev` из России иногда режутся провайдерами. Клиент
  переподключается сам, но если у вас постоянно рвётся — используйте Supabase.

## Обновление кода реле

```bash
cd deploy/cloudflare
wrangler deploy
```

Ключи комнат не меняются: они живут в клиенте, а не в реле.
