# Совместный просмотр через Supabase

Реле на Supabase Realtime: каждая комната — это публичный broadcast-канал
`realtime:party:<АДРЕС>`, где адрес — это `sha256` от ключа комнаты (32
шестнадцатеричных символа). Ни таблиц, ни RLS-политик, ни edge-функций
создавать не нужно: достаточно publishable-ключа проекта. Сам ключ и секрет
комнаты на Supabase не попадают, а содержимое сообщений зашифровано AES-GCM.

## Что понадобится

- аккаунт Supabase (бесплатного плана достаточно);
- проект в регионе **eu-central-1** (ближе всего к России и Европе);
- около трёх минут.

## Настройка

1. Создайте проект на <https://supabase.com/dashboard>.
2. Откройте **Project Settings → API Keys** и скопируйте:
   - **Project URL**, например `https://abcdefghijkl.supabase.co`;
   - **publishable** ключ `sb_publishable_...` (в проектах, созданных до
     перехода на новые ключи, — legacy **anon public** `eyJhbGciOi...`).
3. Больше ничего включать не нужно. Broadcast-каналы доступны из коробки;
   Realtime уже включён на новом проекте.

Ключ передаётся как `apikey` в запросе. `Authorization: Bearer` с
publishable-ключом не используется — так требует новый формат ключей.

Проверить, что Realtime отвечает:

```bash
curl "https://abcdefghijkl.supabase.co/realtime/v1/websocket?apikey=<PUBLISHABLE>&vsn=1.0.0"
# ожидаемо: 101 Switching Protocols (curl может ругнуться на протокол — это нормально)
```

## Как это попадает к пользователям

Обычно своё реле на Supabase никто не поднимает: официальная сборка уже несёт
адрес Cloudflare, а Supabase в ней — резерв. Если вы всё же хотите поставлять
своё реле, его настройки вшиваются один раз, как и у Cloudflare:

1. Задайте `YO_SUPABASE_ENDPOINT` и `YO_SUPABASE_PUBKEY`: в окружении
   при локальной сборке или в GitHub **Settings → Secrets and variables →
   Actions → Variables** для релиза. Альтернатива — `party.json` в корне
   репозитория.
2. Собрать релиз: `build.ps1` передаст их в
   `-ldflags -X party.SupabaseURL` и `party.SupabaseKey`.

Переменные окружения важнее файла; `party.json` сборка не перезаписывает.

Внимание на квоту: проект **общий для всех пользователей сборки**, поэтому 2
млн сообщений в месяц делятся на всех — это примерно 37 часов просмотра в
сутки суммарно. Для публичной сборки основным реле должен быть Cloudflare.

## Подключение клиента без своей сборки

URL и ключ можно ввести в настройках yo: **Совместный просмотр → Провайдер
→ Supabase Endpoint / Supabase Publishable Key**. То же самое можно сделать
файлом `%APPDATA%\yoanime\party.json`:

```json
{
  "supabase_endpoint": "https://abcdefghijkl.supabase.co",
  "supabase_pubkey": "sb_publishable_..."
}
```

Провайдер **Supabase** выбирается в блоке настроек. В форме комнаты провайдер не
выбирается: ключ с буквой `S` сам приведёт гостя на Supabase. Файл перекрывает
вшитые значения.

Для сборки с вшитым ключом:

```bash
go build -ldflags "\
 -X github.com/arfush/yo/party.SupabaseURL=https://abcdefghijkl.supabase.co \
 -X github.com/arfush/yo/party.SupabaseKey=sb_publishable_..." ./cmd/yo
```

Publishable-ключ публичный: он и должен лежать в клиенте. Не вшивайте
`sb_secret_...` и `service_role` — они дают полный доступ к проекту и для
публичных каналов не нужны.

## Почему это бесплатно и не съедает квоту

Бесплатный тариф Supabase считает **доставленные сообщения**: 2 000 000 в
месяц. Комната шлёт:

- heartbeat создателя раз в 4 секунды во время просмотра и раз в 10 секунд
  на паузе;
- одно сообщение на действие: старт, смена серии, пауза, перемотка.

При просмотре 4 часа в день и 10 участниках это примерно 1,1 млн сообщений в
месяц — вдвое меньше лимита. Если смотреть реже, запас растёт.

Дополнительные меры экономии уже в клиенте:

- гость не пингует создателя: смещение часов считается по входящим якорям;
- при рассинхроне правится скорость (`0.94–1.06`), а не шлются новые пакеты;
- ссылки на серии не резолвятся заново без нужды.

## Простой проекта

Бесплатный проект засыпает после 7 дней без запросов, а спящий Realtime не
пускает в комнату. Достаточно раз в неделю открыть дашборд или добавить любой
запрос в **Cron** (Database → Cron Jobs):

```sql
select 1;
```

Задание раз в сутки снимает проблему полностью.

## Ограничения

- Realtime отключает соединение при превышении 100 сообщений в секунду на
  канал — для комнаты это недостижимо.
- Канал адресуется хешем ключа, поэтому в логах Supabase самого ключа нет.
  Содержимое комнаты всегда зашифровано; без секрета ключ комнаты и есть
  приглашение, поэтому не публикуйте его в открытых чатах. Секрет добавляет
  второй фактор: без него чужой якорь не расшифровать.
- Публичное Realtime-подключение живёт не дольше 24 часов. Клиент
  переподключается сам, так что длинный марафон не прервётся.
- Отдельного «списка участников» нет: клиент считает комнату живой, пока
  создатель присылает якоря.
