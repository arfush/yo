# AGENTS.md

Памятка для ИИ-агентов, которые работают с репозиторием **yoanime**. Прочитай её целиком перед первым изменением: здесь описаны архитектура, инварианты и правила, нарушение которых ломает приложение или релизный процесс.

## 1. Обязательное правило: Conventional Commits 1.0.0

**Все агенты обязаны оформлять коммиты по [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/).** Это требование репозитория, а не рекомендация.

Формат:

```text
<type>[optional scope][!]: <description>

[optional body]

[optional footer(s)]
```

Правила:

- `type` — один из `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`, `revert`.
- В проекте дополнительно используется тип `release` — его требует GitHub Actions (см. раздел «Релизы»).
- `scope` опционален; используй имя пакета или подсистемы: `ui`, `playback`, `animelib`, `store`, `library`, `browser`, `kodik`, `updates`, `mpv`.
- Описание — краткое, в повелительном наклонении, со строчной буквы, без точки в конце. Ориентир — до 72 символов.
- Тело коммита объясняет **почему** изменение нужно, а не пересказывает diff. Переносы строк — по 72 символа.
- Несовместимое изменение: `feat(api)!: ...` и/или футер `BREAKING CHANGE: ...`.
- Один коммит — одно логическое изменение. Не смешивай рефакторинг, фичу и правку форматирования.
- Агент обязан сам коммитить завершённую работу и не оставлять изменения только в рабочем дереве. Исключение — коммиты `release:`: их создаёт только пользователь по отдельной просьбе.
- Не добавляй посторонние трейлеры, рекламные подписи и упоминания инструментов, если пользователь об этом не просил.
- Язык сообщений коммитов — английский.

Примеры:

```text
feat(playback): keep the mpv playlist ordered while preloading
fix(animelib): wait for the rate-limit window before retrying
docs: describe the Kodik fallback in AGENTS.md
refactor(store): extract history reordering into a transaction
release: v1.1
```

### Релизные коммиты

`release` — намеренно нестандартный тип, потому что workflow `.github/workflows/release.yml` запускается только при сообщении, начинающемся с `release:`. Формат первой строки:

```text
release: v1.2
```

Допускается и `release: 1.2` (workflow добавит `v`), но в этом репозитории принят вариант с `v`. Всё, что идёт после первой строки, публикуется как описание GitHub Release, поэтому тело релизного коммита должно быть готовым текстом заметок, а не служебными фразами.

Кинопоиск — второй источник контента, и в заметках о релизе он не упоминается. В первой строке и теле `release:`-коммита нельзя писать «Кинопоиск», «Kinopoisk», «Alloha», `internal/kinopoisk`, а также перечислять связанные изменения: сезоны, озвучки Alloha, субтитры, автопропуск по `skipTime`, заголовки mpv. Заметки релиза описывают только изменения AnimeLIB-части; упоминание второго источника — требование владельца проекта, а не техническое ограничение.

Не переписывай историю и не делай force-push без явного указания пользователя.

## 2. Что это за проект

yoanime — десктопное Windows-приложение для ведения личной аниме-библиотеки и просмотра серий через AnimeLIB. Оно:

- принимает ссылку на тайтл AnimeLIB или его slug;
- принимает ссылку на Кинопоиск (`/film/{id}`, `/series/{id}`) и показывает фильмы и сериалы Alloha с сезонами, озвучками и субтитрами;
- показывает озвучки, серии и статус тайтла;
- запускает mpv с очередью серий, автопереходом, продолжением с места и главами;
- хранит историю, прогресс, обложки и настройки локально;
- при первом запуске сама устанавливает Chromium и mpv;
- обновляется из GitHub Releases.

Приложение неофициальное и никак не связано с AnimeLIB и Кинопоиском. Кинопоиск — второй источник, но в заметках о релизе он не упоминается (раздел 1).

## 3. Технологический стек

- **Go 1.26.5**, модуль `github.com/arfush/yoanime`.
- **Gio** (`gioui.org`) — весь интерфейс рисуется вручную, нативных виджетов нет.
- **SQLite** (`modernc.org/sqlite`) — локальная база.
- **Playwright Go + Chromium** — авторизация на сайте и резолв Kodik/Alloha.
- **mpv** — воспроизведение (внешний процесс, управление по IPC).
- **7-Zip-распаковка** (`github.com/bodgit/sevenzip`) — установка mpv.
- **Win32 API** (`golang.org/x/sys/windows`) — трей, кастомное окно, DPI.
- `third_party/npipe` — локальный replace для named pipes на Windows.

Сборка идёт с `CGO_ENABLED=0` под `GOOS=windows`.

## 5. Поток данных

1. `ui.Run` создаёт окно и `application`.
2. `attachWindow` проверяет токен, при необходимости устанавливает Chromium, просит авторизацию, затем устанавливает mpv и показывает главный экран.
3. Ввод ссылки -> `mainWindow.startLoading` -> `library.Fetch` или `library.Load`. `kinopoisk.ParseInput` перехватывает ссылки Кинопоиска ещё до AnimeLIB: для такого тайтла токен не нужен.
4. `library` читает токен, вызывает `animelib.Client`, сохраняет метаданные в `store`, подтягивает обложку. Для Кинопоиска вместо этого работают `kinopoisk.Client` (метаданные + каталог Alloha) и `library.loadKinopoisk`.
5. Страница тайтла вызывает `library.Save` (только по кнопке «Сохранить») и `startPlayback`.
6. `library.PlaybackPlan` строит список серий выбранной озвучки; для Кинопоиска — отдельный `kinopoiskPlan` с ключами `S{сезон}E{серия}`.
7. `playback.Service` резолвит текущую серию (AnimeLIB MP4, иначе Kodik HLS, для Кинопоиска — headless-театр Alloha), запускает mpv и догружает соседние серии в фоне.
8. Прогресс сохраняется в `history`, главы — в `introdb_cache`.

## 6. Ключевые инварианты

### Данные

- Каталог данных: `%APPDATA%\yoanime` (через `os.UserConfigDir`).
- Файлы: `yoanime.sqlite`, `animelib_token.txt`, `browser/`, `covers/`, `mpv/`, `updates.json`, `update/`, `party.json`, `kinopoisk.json`, `yoanime.log`.
- **Списки серий, озвучки, сезоны и URL обложек не кэшируются в SQLite.** Они загружаются заново при каждом открытии страницы тайтла.
- Таблица `history` хранит только выбранную озвучку, серию, позицию и длительность.
- `titles.source` различает источники (`animelib`/`kinopoisk`), `titles.external_id` хранит их идентификатор. Slug Кинопоиска — `kinopoisk:{id}`, чтобы уникальность `slug` не ломалась. Не создавай под источник отдельную таблицу.
- Пользовательский статус (`user_status`) хранится локально и не является статусом релиза AnimeLIB. Значения: `1` — «Смотрю», `2` — «В планах», `3` — «Обожаю», `4` — «Досмотрел», `5` — «Брошено»; по умолчанию `2`. Анонсированный тайтл может иметь только «В планах».
- Проект первого релиза: миграций и совместимости со старыми базами нет. Схема создаётся с нуля; при будущих изменениях схемы миграции нужно добавлять явно.
- Токен нельзя писать в логи, базу, сообщения об ошибках или коммиты.

### Логирование

- Приложение обязано вести журнал в `%APPDATA%\yoanime\yoanime.log` через `log`. Это требование, а не пожелание: без него разбор пользовательских проблем невозможен.
- Новые сетевые, файловые, playback-, обновляющие и фоновые операции должны писать хотя бы одну запись о начале и одну о результате; ошибки — через `log.Error` с контекстом. Не логируй каждый кадр UI и не засоряй журнал обычными кликами.
- Токены, пароли, ключи реле и другие секреты запрещены в журнале. `log` вырезает значения по именам атрибутов (`token`, `password`, `secret`, `key`), но это страховка, а не разрешение передавать секреты.
- Ошибки для пользователя централизованы в заголовке окна (`shell.setError`) и не рисуются внутри экранов. Технические детали остаются только в журнале; пользователь видит короткую русскую фразу.
- Окно журнала открывается кнопкой в футере главного экрана. Кнопка «Скопировать» копирует последнюю ошибку и её контекст, а не весь журнал. После новой ошибки кнопка журнала на 5 секунд становится приглушённо-красной.
- Старые версии не поддерживаются: данные из прежнего каталога `%APPDATA%\yonime` и файл `watchparty.json` не читаются и не переносятся.

### AnimeLIB

- Базовый URL API — `https://api.cdnlibs.org`; заголовки должны имитировать сайт (`Referer`, `Origin`, `Site-Id`, `User-Agent`).
- Без токена защищённые запросы должны возвращать понятную пользователю ошибку на русском.
- Лимит AnimeLIB — около 100 запросов в фиксированное 60-секундное окно. Общий rate limiter в `animelib/rate_limit.go` обязателен: не обходи его, не запускай неограниченный параллелизм и не убирай ожидание после 429.
- Семафор клиента ограничивает одновременные запросы; новые тяжёлые запросы добавляй через существующий клиент.
- `ParseInput` должен принимать и полную ссылку, и slug, и ссылки зеркал.

### Kinopoisk

- Токен AnimeLIB для Кинопоиска не нужен; запросы этого источника не должны попадать в `animelib` rate limiter.
- Ключи серий — плоский список: `"1"` у фильма, `S{сезон}E{серия}` у сериала. Их нельзя прогонять через `animelib.NormalizeEpisodeNumber`; для отображения используй `episodeDisplayLabel`.
- Сезоны живут только в `Title.Seasons` и не кэшируются. У фильма сезонов нет: каталог отдаёт его как сезон 0, и фантомный сезон в UI недопустим.
- Метаданные берутся из неофициального API (v2.2, затем v2.1); при отказе остаётся заглушка с постером `https://st.kp.yandex.net/images/film_big/{id}.jpg` и именем `Кинопоиск #{id}`. Вшитый ключ — часть контракта: не превращай его в обязательную настройку.
- Каталог озвучек читается без браузера: `api/players` обёртки, затем HTML театра с `fileList = JSON.parse(...)`. Хост театра берётся из ответа players, `%APPDATA%\yoanime\kinopoisk.json` — переопределение для форков.
- Потоки резолвит только общий headless Chromium: страница одна, вызовы сериализованы, iframe перенаправляется на нужную серию. Не заменяй это на `net/http`.
- `hlsSource[].quality` у фильма может быть двумя зеркалами VK через `" or "`. В mpv отдавай ровно один валидный URL, а дорожку ищи сравнением со всеми зеркалами.
- Озвучка фильма определяется по первому запросу `.m3u8`: `audioId` в `hlsSource` не равен id перевода, совпадение URL — единственный надёжный признак.
- Заголовки mpv задаются на каждый файл через `set_property http-header-fields` (`Referer` — точный URL театра, `Origin`, `authorizations`). Для файлов AnimeLIB их обязательно возвращать к `animelibStreamHeaders`, иначе после серии Кинопоиска сломается прямой плеер.
- Все `captions`-дорожки добавляются в mpv: дефолтная — `select`, остальные — `auto`, чтобы их можно было переключать из mpv.
- `skipTime` превращается в главы через `metadata.ChapterTitle` (`Opening`/`Ending`). Произвольные и русские заголовки ломают автопропуск: `SegmentFromChapterTitle` знает только английские метки.
- Окно предзагрузки Кинопоиска меньше анимешного: 8 серий вперёд и 2 назад, потому что каждая серия стоит headless-резолва.
- `PlaybackPlan.Source` и `PlaybackPlan.Kinopoisk` — единственный способ ветвления в playback; не определяй источник по slug в глубине сессии.
- Набор качеств у тайтлов разный (BDRip до 1080, ремастер до 2160), поэтому при открытии страницы приложение фоново резолвит первую серию выбранной озвучки через общий headless Chromium (без окон) и получает `Media.Qualities`. Блок качеств рисует стандартные 720/1080/1440/2160, недоступные для озвучки шаги — некликабельными; если озвучка не имеет ни одного стандартного шага, вместо них выводятся её реальные качества. Лестница кэшируется только при сохранении тайтла в историю (таблица `title_qualities`, JSON по именам озвучек) и восстанавливается при следующем открытии; в память кэш live на весь сеанс. Проба не должна запускаться во время воспроизведения и не должна быть ошибкой для пользователя.
- Блок качеств на всех тайтлах называется «КАЧЕСТВО» (без «предпочтительное»). У фильма Кинопоиска выбор не пишется в общую настройку предпочтительного качества — качество фильма выбирается только для этого фильма. Пояснительная надпись под блоками качеств не рисуется.

### Playback

- Одновременно может работать только одна сессия mpv.
- Текущая серия резолвится **до** запуска окна mpv; ошибка должна оставить пользователя в приложении.
- Очередь пополняется окнами: вперёд до 30 серий, назад до 5; для Кинопоиска — 8 и 2. Не резолвь весь тайтл сразу.
- AnimeLIB-плеер имеет приоритет; Kodik — только фолбэк для серий, которых нет в прямом плеере.
- `playlist-pos` в mpv может прийти после `file-loaded`; не привязывай прогресс к событиям без проверки фактической позиции.
- Прогресс сохраняется не чаще раза в 5 секунд, при паузе и при завершении. Позиция < 5 секунд и позиция near-end сбрасываются.
- Главы introdb кэшируются, включая отрицательный результат (`no_data`).
- Автопропуск работает по типам сегментов introdb и настройкам `autoskip_*` в `settings`; каждый сегмент пропускается один раз за файл, чтобы ручная перемотка назад не возвращала seek. У гостя совместного просмотра автопропуск выключен: таймлайном владеет создатель комнаты. Не добавляй для этого Lua-скрипты — mpv управляется через IPC.
- Не блокируй event loop сессии длительными резолвами: используй горутины и существующие мьютексы.

### Совместный просмотр

- По сети ходит только якорь (`State` с позицией и часами хоста), а не поток позиций. Гость экстраполирует позицию сам, поэтому потерянный пакет не рассинхронизирует комнату.
- Провайдеры равноправны: Cloudflare DO и Supabase Realtime используют один и тот же JSON поверх WebSocket (`party`). Новый провайдер добавляется в `transport.go`, `config.go`, `state.go` и, если у него есть свои поля, в блок настроек, без правок остального UI.
- Хост публикует якорь раз в 4 секунды при воспроизведении и раз в 10 секунд на паузе, плюс сразу после паузы, смены серии и перемотки. Не поднимай частоту: от неё напрямую зависит расход квоты Supabase.
- Гость не шлёт периодического трафика, поэтому полуоткрытый сокет (NAT сбросил маппинг, а сервер об этом не знает) незаметен: якоря перестают приходить, но экстраполяция по последнему якорю продолжает «нормально» показывать позицию — а пауза/перемотка хоста до гостя уже не доходят. Если свежий якорь не приходит дольше 15 секунд при играющем плеере, гость шлёт hello через `Session.RequestRefresh` (хост отвечает якорем, дешёво и только по событию) — не превращай это в периодический ping/pong.
- Смещение часов считается по входящим якорям (минимум `local_recv - anchor_host` по окну из 96 сэмплов). Не заменяй это на ping/pong — это лишний трафик.
- Рассинхрон до ~900 мс правится скоростью (`0.94–1.06`), больше — точным seek. Не убирай `--hr-seek=yes`: без него seek округляется до ключевого кадра.
- Управлять воспроизведением может только создатель комнаты. Гость повторяет состояние, но не публикует своё.
- Гость догоняет хост по сериям внутри своего уже разрешённого плейлиста через `Session.JumpTo` (`set_property playlist-pos`), а не перезапуском mpv: резолв серии Кинопоиска стоит секунд, и перезапуск превращает догон в вечную погоню (хост успевает уйти вперёд, пока гость резолвит). Полный перезапуск остаётся только когда серии нет в окне гостя либо сменился тайтл/озвучка (`ErrEpisodeNotLoaded`).
- Публикация якорей хоста и коррекции гостя логируются: `watch-party host anchor`/`guest tick` — на уровне debug, прыжки по сериям, seek/pause/speed и приём guest-контролей — info, ошибки публикации — warn. Это обязательная диагностика рассинхрона комнаты.
- Хост публикует якорь сразу после подключения, даже пустой: для гостя это доказательство, что комната существует. Не убирай этот «hello-ответ» — иначе гость решит, что ключ неверный.
- Реле живут на бесплатных тарифах: не добавляй периодических сообщений сверх перечисленных и не дублируй доставку.
- Реле разворачивается один раз автором сборки: `build.ps1` берёт `YOANIME_PARTY_CLOUDFLARE_URL`, `YOANIME_PARTY_SUPABASE_URL` и `YOANIME_PARTY_SUPABASE_KEY` из окружения, а если их нет — из `party.json` в корне репозитория (в релизе — из одноимённых repository variables). Пользователь не должен настраивать ничего. `%APPDATA%\yoanime\party.json` — переопределение для форков, своих реле и полей в настройках; если файл существует, он полностью перекрывает вшитые адреса, включая пустые поля. Образцы из `party.json` сборка пропускает. Пустая конфигурация должна давать понятную ошибку, а не панику.
- Для Supabase годится только publishable-ключ (`sb_publishable_...`, в старых проектах `anon`). `sb_secret_...`/`service_role` в сборку попадать не должен.

### Kodik

- Kodik `/ftor` требует браузерную сессию. Резолв идёт через headless Chromium, а не через прямой HTTP-запрос.
- Один headless-браузер живёт на сессию; резолвы сериализованы, кэш ссылок — 45 минут.
- Не заменяй Playwright на `net/http` и не пытайся обойти защиту иначе: это уже проверено и не работает.

### Браузер и авторизация

- Пользователь входит на сайте AnimeLIB сам; приложение только открывает сайт и читает сохранённый токен.
- Профиль Chromium persistent, чтобы сессия переживала перезапуск.
- Токен хранится в `%APPDATA%\yoanime\animelib_token.txt` в контейнере Windows DPAPI (пользовательский scope); старый открытый файл мигрирует при первом чтении. Не заменяй DPAPI на обратимое кодирование и не логируй содержимое.
- Токен считается истёкшим за 2 минуты до фактического окончания (`token.ExpiryMargin`).
- `Manager.Close` должен уметь прервать и установку, и авторизацию.

### Обновления

- Источник — последний GitHub Release репозитория `arfush/yoanime` (переопределяется ldflags).
- Обязательна проверка SHA-256; не ослабляй проверки URL, размера и сигнатуры файла.
- Windows блокирует запущенный exe, поэтому замена идёт через `updater` и скрытый `cmd.exe`-хелпер.
- Не удаляй `CheckTarget`, проверку `MZ`-заголовка и очистку временных файлов.
- Стабильный канал принимает версии из одного-двух компонентов (`v1.2`), beta — ещё и патч-версии из трёх (`v1.2.3`). Проверка читает список релизов, а не `/releases/latest`, иначе стабильный канал получил бы патч-релиз.
- Автообновление по умолчанию включено; явное `auto_update=0` в `settings` его выключает навсегда. При запуске доступное обновление показывается карточкой загрузки вместо главного экрана: пользователь должен видеть, что скачивается новая версия, и только после перезапуска попадает на главный экран.
- На первой установке окно обновления ждёт первого главного экрана: проверка релиза идёт параллельно с авторизацией и установкой Chromium/mpv, и найденный релиз подтягивается сразу после них, а не теряется до сворачивания в трей.
- Тихую установку без карточки запускай только когда окно свёрнуто в трей, mpv не запущен и нет комнаты совместного просмотра. Пока окно на экране, автообновление не должно прерывать работу пользователя. Не запускай установку во время воспроизведения.
- Проверки идут при запуске и раз в 30 минут, а после сетевой ошибки — через 5 минут: доступное обновление не должно висеть кнопкой в футере часами. Ошибка карточки при запуске возвращает на главный экран, а не запирает пользователя на экране загрузки.

### UI

- Gio — immediate mode. Не храни указатели на виджеты между кадрами и не мутируй список истории во время `List.Layout`.
- Никаких блокирующих вызовов в `layout`: сеть, диск и mpv — только из горутин.
- Фоновые результаты передаются в UI через каналы и `w.Invalidate()`.
- Когда окно скрыто в трее или уступает экран mpv, анимации должны переставать запрашивать кадры.
- Пользовательские строки — на русском. Комментарии и внутренние ошибки — на английском; ошибки, которые видит пользователь, — на русском.
- Кастомный заголовок и трей реализованы через Win32; не заменяй их стандартным окном без причины.
- Закрытие окна сворачивает приложение в трей. Полностью закрывает только пункт меню трея.
- Сезоны Кинопоиска рисуются полосой внутри блока серий, а его заголовок — «СЕЗОНЫ (a-b)». Выбранная серия всегда принадлежит видимому сезону: не оставляй выделение на серии другого сезона и не показывай полосу для одного сезона.
- У фильма со статусом «Досмотрел» прогресс-бар скрывается целиком — и у Кинопоиска, и у аниме-фильмов.

### Платформы

- Windows — основная и единственная реально поддерживаемая платформа.
- Файлы с Win32-кодом имеют build tag `//go:build windows`; для остальных ОС должны оставаться заглушки, чтобы пакет компилировался.
- Не меняй `third_party/npipe` без необходимости: это локальный replace для named pipes.

## 7. Команды

Все команды выполняются из корня репозитория.

```powershell
# Полная проверка
go test ./...
go vet ./...
gofmt -l .\cmd .\internal .\ui .\party .\log .\tools

# Один тест
go test ./internal/playback -run TestName -v

# Сборка (Windows GUI, без консоли)
.\build.ps1 -Version 1.0 -Arch amd64

# Установщик (Inno Setup скачивается сам при первом запуске; собирается из dist\yoanime_v1.0_amd64.exe)
.\installer.ps1 -Version 1.0 -Arch amd64

# Или через make
mingw32-make build VERSION=1.0 ARCH=amd64
mingw32-make check
```

`build.ps1` выставляет `CGO_ENABLED=0`, `GOOS=windows` и передаёт версию/репозиторий через ldflags. Без `-Version` версия берётся из `internal/version/version.go`. Если заданы переменные `YOANIME_PARTY_*`, адреса реле совместного просмотра тоже вшиваются в exe.

### Подпись сборок

`build.ps1` и `installer.ps1` подписывают exe и установщик, если задан сертификат, и молча пропускают шаг, если его нет. Переменные читает `sign.ps1`:

- `YOANIME_SIGN_PFX` — путь к `.pfx`;
- `YOANIME_SIGN_PFX_BASE64` — тот же `.pfx` в base64 (для GitHub Secrets);
- `YOANIME_SIGN_PFX_PASSWORD` — пароль `.pfx`;
- `YOANIME_SIGN_THUMBPRINT` — отпечаток сертификата, уже установленного в хранилище.

В release workflow сертификат берётся из секретов `YOANIME_SIGN_PFX_BASE64` и `YOANIME_SIGN_PFX_PASSWORD`; без них релиз собирается неподписанным.

Доверенную подпись даёт только сертификат публичного УЦ. Самоподписанный сертификат годится для локальной проверки, но на чужих машинах Windows его не признаёт и предупреждение SmartScreen не убирает.

Интеграционный тест авторизации запускает настоящий Chromium и по умолчанию пропускается:

```powershell
$env:YOANIME_AUTH_TEST = "1"
go test ./internal/browser -run TestAuthorizeIntegration -v
Remove-Item Env:\YOANIME_AUTH_TEST
```

## 8. Правила разработки

- Соблюдай `gofmt`; код должен проходить `go vet`.
- Следуй стилю окружающего кода: небольшие функции, ранние возвраты, комментарии по делу.
- Новые зависимости добавляй только при явной необходимости и объясняй это в PR/коммите.
- Ошибки оборачивай через `%w` и добавляй контекст.
- Для новых неочевидных решений добавляй короткий комментарий, объясняющий причину.
- Тесты не должны ходить в сеть, запускать Chromium/mpv или зависеть от реального `%APPDATA%`. Используй `t.TempDir()`, `httptest` и внедряемые зависимости.
- Покрывай тестами чистую логику: парсинг, выбор серии/озвучки, прогресс, rate limit, обновления, UI-хелперы.
- Не коммить `yoanime.exe`, `dist/`, базы, токены, `updates.json`, `.idea/` и прочие локальные артефакты.
- Перед коммитом проверь `git status` и `git diff`: в индекс не должны попасть секреты и случайные файлы.

## 9. Передача работы в основной проект

Агент работает в отдельном worktree с detached HEAD: его коммиты не видны в
основном чекауте, пока их туда не переложат. Основной проект — единственный
источник истины для пользователя: в нём он запускает `go test`, собирает exe и
делает релиз. Задача не считается выполненной, пока коммит не оказался в `main`
основного чекаута.

Основной чекаут в этом окружении —
`C:\Users\Nazar Bykasov\projects\yonime` (имя каталога осталось от прежнего
названия приложения), ветка `main`. Точный путь всегда можно получить через
`git worktree list`: это единственная запись с веткой `main`, остальные —
worktree агентов с detached HEAD.

### В начале задачи

Сверь базу worktree с `main` (`git -C "<main>" log --oneline -1`). Если `main`
ушёл вперёд, сразу перебазируйся на него: разбирать расхождение в конце, когда
уже написана куча кода, дороже, а причина расхождения обычно в том, что worktree
создали от старого коммита.

### Порядок действий

1. Проверить, что основной чекаут чист и не ушёл вперёд:
   ```powershell
   git -C "<main>" status --short --branch
   git -C "<main>" log --oneline -1
   ```
2. Перебазировать свою работу на верхушку `main`. Перебазируется ветка агента,
   а не `main`:
   ```powershell
   git rebase <main-tip>
   ```
3. Повторить проверки после rebase: новые коммиты в `main` могли задеть те же
   файлы. `go build ./...`, `go vet ./...`, `go test ./...`.
4. Перемотать `main` только fast-forward-ом:
   ```powershell
   git -C "<main>" merge --ff-only <sha>
   ```
5. Убедиться, что коммит на месте и дерево чистое:
   ```powershell
   git -C "<main>" log --oneline -1
   git -C "<main>" status --short
   ```
6. Написать пользователю SHA и первую строку коммита, на который теперь
   указывает `main`.

### Жёсткие правила

- Только `--ff-only`. `merge` без fast-forward, `reset --hard`, `rebase` и
  `cherry-pick` прямо в основном чекауте запрещены: там может лежать
  незакоммиченная работа пользователя.
- **Не делать `git push`** и не трогать `origin` без явной просьбы. Локальный
  `main` вправе опережать `origin/main`.
- Если основной чекаут грязный — остановиться и перечислить мешающие файлы. Не
  прятать правки через `stash` и не откатывать их.
- Если fast-forward невозможен, перебазировать свою работу на актуальный `main`
  и повторить шаги. Мержить свою ветку в `main` с созданием merge-коммита
  нельзя.
- Конфликты разрешаются только в worktree агента. Если конфликт затрагивает
  чужую незавершённую работу или уверенности нет — остановиться и спросить.
- Коммиты `release:` по-прежнему создаёт только пользователь.
- Worktree после передачи оставлять как есть: он нужен для следующих правок.

## 10. Релизы

Релиз полностью автоматизирован:

1. Изменения попадают в `main`.
2. Коммит с первой строкой `release: vX.Y` запускает workflow. Версия из трёх компонентов (`release: vX.Y.Z`) публикуется как GitHub pre-release и попадает только в beta-канал.
3. Workflow прогоняет тесты, собирает `amd64`, `arm64`, `386`, считает SHA-256 и публикует GitHub Release. Для каждой архитектуры в релизе два файла: портативный `yoanime_vX.Y_<arch>.exe` и установщик `yoanime_vX.Y_<arch>_setup.exe` (рядом с ними — `.sha256`). Если хотя бы одного exe нет, публикация падает.
4. Тело релизного коммита становится описанием релиза; если оно пустое, GitHub генерирует заметки сам.

Не создавай теги и релизы вручную в обход workflow. Не меняй формат `release:` без обновления парсера в `.github/workflows/release.yml`.

## 11. Известные ловушки

- **Запущенный exe нельзя перезаписать** — только через `updater` после выхода процесса.
- **Win32-трей живёт в отдельном message loop.** Вызовы `ShowWindow` из UI-потока могут заблокировать оба потока; скрытие уже вынесено в горутину.
- **`playlist-pos` приходит с задержкой.** Для прогресса и resume используй фактическую позицию, а не только событие.
- **Gio List нельзя мутировать во время layout.** Удаление строк обрабатывается после раскладки.
- **Скрытое окно не должно крутить анимации** — иначе процесс ест CPU в трее.
- **AnimeLIB отвечает 429 без полезного `Retry-After`.** Опирайся на локально отслеживаемое окно.
- **Kodik без браузера не резолвится.** Не «оптимизируй» это в HTTP-клиент.
- **`hlsSource[].quality` фильма — это не URL, а два зеркала через `" or "`.** Сырая строка даёт в mpv `URL using bad/illegal format`; нормализуй её до одного адреса.
- **Заголовки mpv живут до конца файла и переходят на следующий.** После серии Кинопоиска их нужно вернуть к заголовкам AnimeLIB, иначе прямой плеер получит чужой `Referer`.
- **Сборка только с `CGO_ENABLED=0`.** Не добавляй зависимости, требующие cgo.

## 12. Definition of Done

Перед завершением задачи:

- [ ] `gofmt` не находит изменений;
- [ ] `go vet ./...` проходит;
- [ ] `go test ./...` проходит;
- [ ] затронутая логика покрыта тестами или объяснено, почему нет;
- [ ] проверен ручной сценарий на Windows, если менялся UI, mpv, трей или установка;
- [ ] в диффе нет секретов, баз, бинарников и локальных файлов;
- [ ] коммит оформлен по Conventional Commits 1.0.0;
- [ ] работа перебазирована на актуальный `main` и `main` основного чекаута перемотан на неё через `merge --ff-only` (раздел 9);
- [ ] для релиза — первая строка `release: vX.Y` и готовые заметки в теле.
